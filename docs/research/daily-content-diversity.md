# 每日童话／历史故事选题去重与多样性研究

研究日期：2026-11-21（系统 `date`：CST）。范围：只读当前工作区相关代码和有限文档、限时访问公开一手资料；不调用付费 LLM，不修改产品代码或已有用户修改。

## 已完成的仓库核查与初步结论

- 在 `docs` 深度 3 的文件名检查、深度 2 的目录检查及限定 Markdown 检索中，未发现既有 research／调研笔记目录惯例，因此使用本路径。
- `services/app/free_module.py:168–203`：历史按模块名保存标题，每模块最近 **20** 项；`_recent_titles` 默认只取 **8** 项。不是完整故事历史，也没有故事 ID、梗概或语义校验。
- `_llm_content`（约 221–273 行）：把最近标题放入 prompt，发送当前日期、模块主题与风格；`temperature=0.9`；调用一次文本生成，提取 JSON 并截断字段，没有生成后故事级重复判定或选题重试。
- `render_free_fps6`（约 579–653 行）：缓存命中不重新生成；未命中调用文本生成后立即记录标题，再生成图片／降级文字。已有两次尝试针对图片平铺检测，不是选题去重。记录的是生成尝试，不能直接解释为用户实际展示历史。
- `pick_module` 的日轮换是**模块级**轮换，不是模块内部故事轮换；图片内容哈希也是渲染字节指纹，不是故事身份。
- **静态核查只能说明防重约束薄弱，不能声称已复现线上重复根因。**未读取实际历史、线上日志、密钥或环境凭据，未执行生成。

初步设计建议（待下文引用支持）：将“选哪个故事”从“如何写与画”中分离，以规范化故事身份和持久化历史做硬排除；优先小型可审校题库加无放回轮换，而非单纯提高 temperature。embedding 可补充发现改名复述，但不应单独决定故事身份或历史真实性。

## 简明结论

1. **把多样性作为有状态的选择约束，而不是一句“每天不同”。**官方文档明确每次文本请求独立、无状态，历史需要显式提供或由应用管理 [S1]。temperature 改变采样随机性 [S2]；据其机制可推导，它不保存已选故事集合，不能保证故事不重复（此为机制推论，不是对本服务商的实测）。
2. **最适合本仓库的第一步是小型策展题库＋稳定故事 ID＋持久化无放回轮换／冷却期**，让 LLM 负责改写与画面描述，不再独立决定故事身份。已有模块配置、缓存与降级流程可保留；这是本研究的设计建议，不是某框架或全行业强制标准。
3. **标题去重只宜作廉价前置过滤。**同一故事可以改标题、翻译名或换场景；不同事件也可能同名。用故事 ID、别名映射、事件梗概与必要的人工审校确认身份；embedding 是补充信号，不是身份真值。
4. **先选题并验证，再花钱出图；重试必须有次数和总时限。**不合格输出不能直接进入展示历史；缓存、生成记录、已发布记录和设备确认展示应区分。
5. **真实性是独立维度。**结构化输出可以约束 JSON 结构，但官方明确仍可能出错 [S3]；历史题材应由有出处的事实卡生成，史实、传说、小说演义必须标记，不用“看起来合理”代替证据。

| --- | --- | --- | --- |
| 状态化历史排除 | [S1] 明确独立请求无状态、可显式传历史；建议服务端维护 `story_id` 集合并先过滤候选，而非仅靠 prompt 遵守 | 长期、跨重启防止重复选择 | prompt 内历史只作辅助；上下文长度和指令遵守均有限。持久化损坏不能悄悄当作从未展示；告警并复用安全内容或回退 |

| 规范故事 ID／别名 | 建议题库由应用分配稳定 ID，别名表处理简繁、译名、简称；Unicode 规范化、空白／标点清理只作字符串预处理 | 同故事改名、同故事不同画面的归并 | 不让 LLM 随意发明 ID；同名异事用来源、人物、事件区分。童话的不同版本是否算同故事需先定业务口径；可设 `story_family_id` 和 `version_id`。文本规范化不等于语义等价 |
| 候选池无放回抽样 | [S5] 官方 `random.sample` 说明无放回抽样，`shuffle` 打乱序列；建议对**唯一 ID 列表**洗牌，持久化队列／游标，逐次取用 | 一个周期内可验证的不重复与全池覆盖 | 每天重新调用 `sample(pool, 1)` 仍会跨日重复；必须持久化消耗状态。输入有重复 ID 也会破坏业务唯一性。池耗尽后显式开启新周期，并检查跨周期冷却期 |
| 覆盖轮换／冷却期 | 建议按朝代、地区、作者、主题、主角分层；优先覆盖不足层，再从该层未用 ID 中选；设置故事及人物／主题冷却期 | 避免长期只选热门故事或连续同类型 | 标签分层与“未用优先”是可审计策略，但不是本次检索核实的统一行业标准。约束冲突时先放宽软主题配额，不无声解除故事硬排除；可告知题库不足 |
| 语义去重／embedding | [S4] 展示文本编码、相似度矩阵与余弦相似度，较高分表示更相似；建议编码“故事身份描述＋人物＋核心事件＋梗概”，而非只编码标题或绘画风格 | 发现改名复述、未知别名，辅助开放式题材归并 | 相似度不是“同一故事概率”，不存在本次可证实的通用去重阈值。同人物不同事件易误杀，同故事不同场景易漏判；中文／古文、文本长度、模型和版本均需本地标注集校准。服务失败时回到 ID 题库，不放行未经验证的开放候选 |
| MMR 多样性重排 | [S6] 官方实现按 `λ × 相关性 − (1−λ) × 与已选集合最大相似度` 贪心选择，先取最相关项，再迭代 | 从多个合格候选中平衡主题相关与彼此差异 | 这是所核实开源实现，不称行业标准。MMR 默认比较当前已选集合，不自动读取跨日历史；`k=1` 时只取最相关项，不产生批内多样性收益。先做历史硬排除，再用于未来多日计划；加入历史惩罚是额外设计，不冒充该实现自带功能 |
| 有界生成—验证—重试 | 建议程序校验结构、题库成员、故事身份、历史、事实约束；失败反馈明确原因，再试有限次数 | 让“请勿重复”变成可执行验收 | 重试可能持续失败且增加成本，必须设全链路预算；穷尽时取审校题库备用项、复用并标明旧卡或回退照片，而非无限生成 |
| JSON／结构化输出 | [S3] 约束完成且非拒绝响应的 schema；仍需处理拒绝、截断和 API 错误，业务规则自行校验；明确仍可能有错误 | 字段、类型、允许 ID 枚举（端点支持时） | 不保证故事新颖、史实正确或正文与 ID 一致。本代码当前只是提示“只输出 JSON”加解析，尚非经 API schema 约束；不能假定兼容端点支持所有供应商特性 |

### embedding 阈值应如何落地（设计建议）

- 先人工标注“同故事改名／换场景／不同译名”正例，以及“同人物不同事件／相似母题但不同故事”难负例；按故事族划分校准集与测试集，避免相同故事泄漏。
- 对每个候选检索历史 Top-k，以最大相似度作**待判信号**；设置高置信拒绝区、低置信通过区、中间待审区。具体数值由目标误杀率／漏判率选择，本研究不提供未经校准的 `0.8` 等通用阈值。
- 对已知 ID 的题库成员，ID 判定优先；语义分数用于质检、别名发现和主题多样性，不以高相似度直接认定两件史实为同事。
- 固定并记录 embedding 模型／版本、输入模板与向量维度；更换模型重新编码和校准。小池可本地线性扫描，无须先引入向量数据库；向量缓存按故事及版本复用。

## 针对本仓库的最小建议（不涉及本次实现）

### 推荐分阶段，而非一步上复杂检索框架

| 路线 | 仓库适配及质量 | 成本 | 主要故障处理 |
| --- | --- | --- | --- |
| 轻量历史增强 | 保存规范化标题、别名、梗概、时间及 ID；代码侧排除，历史不必全塞 prompt。适合先止住明显重复，但未知故事身份仍难可靠识别 | 本地存储／校验很低；若用开放生成，仍有有限重试的额外文本费用 | 历史读取／写入失败可观测；不静默清空；候选不合格则备用题库或照片 |
| embedding 增强 | 在轻量层上补充开放内容、同故事改名的检测；只有已测出明显漏判且题材开放时再加 | 本地模型有部署／内存成本；远程模型有网络、隐私和按量成本；历史向量可缓存。小规模没必要先部署向量库 | 超时、模型变更、灰区走 ID 候选池／审校，不默认“检测失败等于无重复” |
| 策展题库＋无放回轮换（首选） | 童话／历史故事身份相对可列举，易定义事实边界和来源；先确定故事，再改写正文及插画，和现有生成渲染职责可分离 | 首次选题、别名整理、史料／年龄适宜性审校是主要人工成本；每天无需额外 LLM 选题调用，可用模板降本 | 枯竭前告警；显式进入新周期或回退；事实卡不足不让模型自动补造史实 |

**建议最小数据与流程：**

1. 题库记录 `module_id, story_id, story_family_id, canonical_title, aliases, synopsis, people, era, theme_tags, source_refs, factuality_label, approved_version`。模块使用稳定 ID，避免仅因模块改名丢失历史；童话和历史的同族故事是否共享排除域由产品定义。
2. 历史至少记录 `story_id, module_id, scheduled_slot, status, created_at, published_at, content_version`，不再只有 20 个标题。历史保留长度由“不重复多久”目标决定，按时间／周期管理，而非任意固定 20 项。旧标题用已知别名尽力迁移，无法归并标记 unknown，不伪称历史完整。
3. 从已审校池排除已发布冷却期内 ID → 按覆盖／未用优先选出一个 → 原子预占槽位与故事 ID → 给 LLM 提供确定的事实卡和 ID，只生成文案及画面描述 → 验证 → 出图／文字降级 → 发布时提交记录。事务、唯一槽位约束或锁用于避免并发拿到同一故事；失败预占需释放或有到期机制。
4. 例示预算：文本生成总共最多 2 次（包括首次），并设文本阶段总截止时间，例如 40 秒；每次请求超时不得超过剩余预算，重试前先检查余额。**这是待配置建议，非既有行为**；现有文本请求单次 30 秒，图片链路可能更长，图片预算应另设且不能挤占无限重试。出图前校验，防止重复项先花图像成本。
5. 校验 `story_id` 必须等于预选题、正文／人物不得越过事实卡边界、故事历史排除合格。schema 和字符串校验无法独立证明事实一致，重要史实需人工审校的来源内容与抽样审核；不要为每个项目默认额外付费 LLM 裁判。
6. `refresh=True` 预览不应直接算“已展示”；建议分离 preview／reserved／generated／published／displayed。服务端若没有设备展示回执，仅能报告“已发布”，不可当成真实曝光。现有缓存应保留同一时段幂等性，避免设备轮询消耗多个题目。
7. 候选池耗尽：先调整软主题偏好，再在满足冷却期的已审校项中按最久未用选；若仍无合格项，明确题库不足并回退照片／安全备用卡。不承诺有限题库永久不重复：若目标是每天一个、连续 365 天不重，至少需要 365 个合格唯一故事；模块非每日展示时按实际展示次数计算。

### 历史真实性与题库来源

**设计建议，不是本次已核实的史料内容：**为每个历史故事附原始文献名称、卷／章／页或稳定链接、采用版本与译注来源；优先机构数字馆藏、校勘出版物／可靠整理本。原始史料也是记述，不自动等于现代已证实事实；涉及争议或晚出传说，标明“据某书载”“传说”并保留不确定性。将演义、成语传说和可核实事件分库／分标签，避免统称史实。

童话题库保留作者／采集者、作品、版本、译名与版权状态；公版故事不代表现代译文、插图或某网站数据可任意商用。先审原故事再做适龄改写，避免把模型熟悉的影视改编细节误作原作。故事族与版本的归并由策展口径定义，不由标题相似度决定。

本次尝试访问 Project Gutenberg 的 Grimm 书目及文本，以及中国哲学书电子化计划《史记》页面，均未取得可用正文；另一次美国国会图书馆展览页面访问被拒。因此**没有在本次核实任何具体历史故事真实性、完整题库、版权许可或史料版本**；这些平台只能列为待后续核查的候选入口，不能据此宣称题库已经可用。详见限制表。

## 测试与评估：以故事身份和覆盖为准

无需调用付费模型即可先用固定候选／假响应做离线测试；以下为后续验收建议，本次未执行产品测试或在线 A/B。

- **故事级窗口重复率**：对每次已发布故事，检查前 W 天（或前 K 次同模块发布）是否含同 `story_family_id`；重复发布次数／窗口内总发布次数。另报精确 `story_id` 重复率；未归并项单报占比及人工抽检，不能算作新故事。标题不同、画面不同不算成功。
- **题库覆盖率**：窗口内已发布唯一合格故事 ID 数／该窗口可选题库唯一 ID 数；另按朝代、人物、主题、作者分别报覆盖与最长未覆盖时间，避免只用总体数字掩盖偏好。题库版本和合格集口径需固定或逐日记录。
- **轮换性质**：N 个唯一候选的完整一周期应发布 N 个不同 ID；跨周期不违反冷却期。同槽位重复请求／缓存命中不新增发布记录。用时间推进模拟 30／90／365 天，而非只跑两天看标题。
- **语义检测指标**：标注集上的同故事检出 precision／recall、误杀率、漏判率、灰区比例；分开统计同人物异事件、简繁／译名、换场景、短标题等难例。模型变更后重新测，不能只展示几个相似度示例。
- **真实性和适龄性**：来源可追溯率、人工抽样事实错误率、传说／演义标记正确率；记录抽检样本量。MMR 分数、schema 通过率均不能替代这些指标。
- **成本与可靠性**：每张成功发布卡片的文本调用次数、图像调用次数、费用、耗时 P50／P95、重试耗尽率、回退率、历史落盘失败率、并发预占冲突率。记录失败原因，但不记录密钥或完整敏感请求。
- **关键故障用例**：历史缺失／损坏／写失败、模块改名、两个进程同槽位生成、预览后未发布、图片失败、重启恢复、未知别名、候选枯竭、模型拒绝／截断／非法 JSON／合法 JSON 但 ID 错误、embedding 不可用、事实卡外人物或事件。
- **对照实验**：同一固定题库／模块和模拟日期下，比较现有“20 项存储／8 标题提示”、ID 硬排除、ID＋覆盖轮换、可选 embedding／MMR；实际 LLM 效果需另行授权实测。不能把离线调度保证冒充已改善线上故事质量。
