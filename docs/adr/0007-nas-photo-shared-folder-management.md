# NAS photo 单一共享目录 + 可管理文件夹，不做每人一夹

> 修订 ADR-0005：保留「分类 = photo 第一层文件夹、一照一分类、不打标」
> 与哈希迁移语义；解除「不可改名」限制（NAS 文件夹现在支持改名）。
> 取消历史上的「每人 Frame_<名字> 独立上传文件夹」机制。

NAS `/volume1/photo` 是唯一共享照片目录与最终存储：全家共用，不再按人
建 `Frame_<名字>` 文件夹。管理台可在 photo 里新建文件夹、重命名、删除
空文件夹，上传照片到任意子文件夹或根目录（未分类）。

## Context

- 原家庭共享上传按「你的名字 → Frame_<名字>」隐式建夹，每人一夹结构
  分散、难整理；用户要的是共用同一个 photo 目录、按主题自由建夹。
- ADR-0005 禁止改名的原因是「rsync 镜像同步会覆盖手动标注」——现在
  改名是显式操作（NAS 与镜像同步 mv），不再与同步冲突。
- pull（NAS → 本地镜像）继续由 sync_nas.sh 定时/手动执行，分析与
  每日精选仍在本地跑；上传与文件夹操作反向推回 NAS，双向闭环。

## Decision

- **上传**（`POST /analysis/upload`）：落本地镜像 `PHOTO_LIB_DIR/[folder/]<relpath>`
  后增量 rsync 推回 NAS；`folder` 缺省/空 = photo 根目录（照片归
  「未分类」），根目录模式只推散照（`--exclude=*/`），不触碰子文件夹。
- **管理台上传目标 = 当前选中的分类 tab**（无下拉框）：选中具体分类
  即传该文件夹，「全部 / 未分类」= 根目录。
- **文件夹管理**（`/analysis/folders`，NAS 先行、本地镜像随动）：
  - 新建：SSH `mkdir` NAS photo 下新文件夹，本地镜像同步创建；
  - 重命名：SSH `mv`（先探测目标不存在，防 `mv a b` 把 a 移进 b），
    本地镜像 mv + 评分记录按路径段边界替换前缀并改写分类（等价于
    一次显式「移动」迁移，评分文案保留），时段绑定与手动精选联动改写；
  - 删除：SSH `rmdir`（只删空目录）+ 本地 rmdir，连带清理该分类
    残留评分记录，时段绑定置空（回全库）。
  - NAS 不可达：文件夹管理失败并明确报错（503）；上传仍先落本地
    镜像，推 NAS 失败记日志，下次上传同文件夹时增量补推。
- 「未分类」是保留分类（photo 根目录散照 / 内容库上传图），不对应
  文件夹，不可新建、重命名或删除。
- 内容库单图归档到 NAS（push_content_image）不恢复：内容库与照片库
  保持各自职责，删内容库图片连带清理评分记录与「推送到显示」绑定。

## Consequences

- 文件夹列表以本地镜像磁盘为准，镜像缺失（尚未同步）时回退 SSH 实际
  列表；NAS 掉线时管理台仍能浏览已同步照片。
- 重命名文件夹等价于批量「移动」：无需重新分析；preview_cache 以
  路径+mtime 为键，旧缓存自然失效成孤儿，不主动清理（无害）。
- 删除文件夹必须先清空照片——刻意不做「连照片一起删」，空文件夹操作
  可安全重试；要清空某分类在 NAS 侧或本地删除照片后同步收敛。
- pull 与 push 共用 rsync 增量语义：上传推过的照片不会被下次 pull
  重复传输；NAS 侧手动整理（建/改/删文件夹）经 pull 收敛到镜像，
  评分记录由哈希迁移语义（ADR-0005）自动跟随。
