# FPS6 设备格式协议（v1）

FramedPhoto 服务端与设备端之间的图片交换格式，与 GDEB0709E01 驱动布局一一对应。

## 文件结构

```
偏移   长度   内容
0      4      magic "FPS6"
4      4      width  (u32 LE) = 1200
8      4      height (u32 LE) = 1600
12     1      format = 1（4bit 双 IC 布局）
13     1      palette_version = 1
14     6      reserved（置 0）
20     960000 数据区（1200*1600/2 字节）
```

## 数据区布局（format=1）

对应硬件：屏幕由 2 颗 GDEP133C02 驱动 IC 拼接（各 600 像素宽）。

```
一行（600 字节 = 1200 像素 @ 4bit/像素）:
┌────────────── 300 B ──────────────┬────────────── 300 B ──────────────┐
│ IC0（屏幕右半 x=600..1199）        │ IC1（屏幕左半 x=0..599）          │
│ 字节 k: 像素对 (1198-2k, 1197-2k) │ 字节 k: 像素对 (598-2k, 597-2k)   │
└───────────────────────────────────┴──────────────────────────────────┘
```

- 每字节 2 像素：**高 nibble = 偶数像素**（x 更小的），低 nibble = x+1
- **行内像素从右到左**：字节 0 是屏幕最右的像素对
- 全帧数据 = 逐行拼接（y 从 0 到 1599，行号在 IC0/IC1 内部均从 0 开始）
- 设备端发送顺序：先 IC0 全部 1600 行（每行 300B），再 IC1 全部 1600 行（每行 300B）——见 `gdeb0709e01_display_image()`

## 颜色 nibble

| nibble | 颜色 | 近似 RGB |
| --- | --- | --- |
| 0x0 | 黑 | (0, 0, 0) |
| 0x1 | 白 | (255, 255, 255) |
| 0x2 | 黄 | (255, 150, 0) |
| 0x3 | 红 | (255, 34, 34) |
| 0x5 | 蓝 | (0, 70, 200) |
| 0x6 | 绿 | (0, 150, 60) |

> 无 0x4 编码。RGB 值仅为近似，实际以数据手册色域为准。

## 转换链路（服务端）

```
原始图片 → cover 缩放至 1200x1600 → 6 色量化（Floyd–Steinberg 抖动）
         → 行内右→左 + 双 IC 拆分 → FPS6 数据区
```

实现：`services/app/epd_image.py`（`prepare_image` / `preview_png`）。

## 设备端对接

`firmware/components/gdey_epd/`：

- `gdeb0709e01_display_image(dev, frame, len)`：整帧刷入（逐行转发，不复制）
- `gdeb0709e01_begin / send_ic_row / next_ic / end`：流式接口（HTTP 边下边刷 / 图案生成用）

字节序注意：驱动以 `SPI 8-bit 命令相位` 发送，nibble 高位先出，与数据区编码一致，无需转换。
